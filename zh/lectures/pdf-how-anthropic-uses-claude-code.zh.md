# Anthropic 团队如何使用 Claude Code

Anthropic 内部团队正在用 Claude Code 重塑各自的工作流，让开发者与非技术岗位的同事都能承接复杂项目、自动化任务，并弥合此前限制其生产力的技能鸿沟。

通过与自家 Claude Code 重度用户的访谈，我们收集了不同部门如何借助 Claude Code 的洞察、它对工作的影响，以及供其他正在考虑引入该工具的组织参考的建议。

## Claude Code 用于数据基础设施

数据基础设施（Data Infrastructure）团队负责为全公司各团队组织所有业务数据。他们用 Claude Code 自动化日常的数据工程任务、排查复杂的基础设施问题，并为技术与非技术团队成员创建有文档记录的工作流，使他们能够独立访问和操作数据。

### Claude Code 主要使用场景

**用截图调试 Kubernetes**

当 Kubernetes 集群宕机、无法调度新的 Pod 时，团队用 Claude Code 来诊断问题。他们把仪表盘（dashboard）截图喂给 Claude Code，后者逐级引导他们浏览 Google Cloud 的 UI 菜单，直到发现一条提示 Pod IP 地址耗尽的告警。随后 Claude Code 给出了创建新 IP 池并将其加入集群的确切命令，从而无需引入网络方向的专家。

**面向财务团队的纯文本工作流**

团队向财务部门的成员演示了如何编写描述其数据工作流的纯文本文件，然后把这些文件加载进 Claude Code 以实现全自动执行。没有编程经验的员工可以描述诸如「查询这个仪表盘、获取信息、运行这些查询、产出 Excel 输出」这样的步骤，Claude Code 便会执行整个工作流，包括主动询问日期等必需输入。

**面向新员工的代码库导航**

当新的数据科学家加入团队时，会被引导使用 Claude Code 来熟悉其庞大的代码库。Claude Code 会阅读他们的 Claude.md 文件（文档），为特定任务定位相关文件，解释数据管道（data pipeline）的依赖关系，并帮助新成员理解哪些上游数据源最终流入仪表盘。这一做法取代了传统的数据目录与可发现性（discoverability）工具。

**会话结束时的文档更新**

团队会在每项任务结束时，让 Claude Code 总结已完成的工作会话并提出改进建议。这就形成了一个持续改进闭环：Claude Code 依据实际使用情况帮助打磨 Claude.md 文档与工作流说明，使后续迭代更有效。

**跨多个实例的并行任务管理**

在处理长时间运行的数据任务时，他们会在不同仓库中为不同项目打开多个 Claude Code 实例。每个实例都保持完整上下文，因此当他们数小时甚至数天后切回来时，Claude Code 仍清楚记得此前在做什么、进行到哪里，从而在不丢失上下文的前提下实现真正的并行工作流管理。

## Claude Code 用于数据基础设施

### 团队成效

**无需专业知识即可解决基础设施问题**

借助 Claude Code 诊断问题并给出确切的修复方案，解决了通常需要引入系统或网络团队同事才能处理的 Kubernetes 集群问题。

**加速上手（onboarding）**

新的数据分析师与团队成员能够快速理解复杂系统，无需大量指导即可做出有实质意义的贡献。

**增强支持工作流**

能够处理大得多的数据量并识别异常（例如同时监控 200 个仪表盘），这是人工审查不可能完成的。

**实现跨团队自助服务**

没有编程经验的财务团队现在可以独立执行复杂的数据工作流。

### 数据基础设施团队的实用建议

**编写详尽的 Claude.md 文件**

你在 Claude.md 文件中把工作流、工具和期望记录得越好，Claude Code 的表现就越好。这让 Claude Code 在已有既定模式的例行任务（例如搭建新的数据管道）上表现出色。

**处理敏感数据时用 MCP 服务器而非 CLI**

他们建议使用 MCP 服务器（MCP Server）而不是 BigQuery CLI，以便对 Claude Code 能访问的内容保持更好的安全控制——尤其是在处理需要留痕或存在潜在隐私顾虑的敏感数据时。

**分享团队使用会话**

团队组织了分享会，让成员相互演示各自的 Claude Code 工作流。这有助于传播最佳实践，并展示他们自己未必能发现的不同用法。

## Claude Code 用于产品开发

Claude Code 团队用自家的产品来构建 Claude Code 的更新，扩展该产品的企业级能力与智能体循环（agentic loop）功能。

### Claude Code 主要使用场景

**用自动接受模式快速做原型**

工程师通过启用「自动接受模式」（auto-accept mode，快捷键 shift+tab）并搭建自主循环（Claude 写代码、运行测试、持续迭代）来实现快速原型开发。他们会把不熟悉的抽象问题交给 Claude，让它自主工作，然后审阅完成度约 80% 的方案，再接手做最终打磨。团队强调要从干净的 git 状态开始，并定期提交检查点（commit checkpoint），这样一旦 Claude 跑偏，就能轻松回退错误的改动。

**核心功能的同步编码**

对于涉及应用业务逻辑的更关键功能，团队与 Claude Code 同步协作，给出带有具体实现指令的详细提示词（Prompt），并实时监控过程，以确保代码质量、符合风格指南（style guide）和架构合理，同时让 Claude 处理重复性的编码工作。

**构建 Vim 模式**

他们最成功的异步项目之一，是为 Claude Code 实现 Vim 键位绑定。他们让 Claude 构建整个功能（尽管它并非优先事项），最终实现中约 70% 来自 Claude 的自主工作，只需少数几次迭代即告完成。

**测试生成与缺陷修复**

他们在实现功能之后用 Claude Code 编写全面的测试，并处理拉取请求（Pull Request）评审中发现的简单缺陷修复。他们还利用 GitHub Actions 集成，让 Claude 自动处理拉取请求上的评论，例如格式问题或函数重命名。

**代码库探索**

在处理不熟悉的代码库（例如单体仓库（Monorepo）或 API 一侧）时，团队用 Claude Code 快速理解系统的运作方式。与其等待 Slack 回复，他们直接向 Claude 询要解释和代码引用，从而在上下文切换（context switching）上节省大量时间。

## 团队成效

- **功能实现更快**：成功实现 Vim 模式等复杂功能，其中 70% 的代码由 Claude 自主编写。
- **开发速度提升**：可以快速原型化功能、迭代想法，而不会陷入实现细节之中。
- **借助自动化测试提升代码质量**：Claude 生成全面的测试并处理常规缺陷修复，在减少人工投入的同时维持高标准。
- **更好的代码库探索**：团队成员无需等待同事回复，即可快速理解单体仓库（monorepo）中不熟悉的部分。

## Claude Code 团队的核心提示

- **构建自给自足的闭环**：让 Claude 通过自动运行构建、测试与 lint 来验证自己的产出。这使 Claude 能够更长时间地自主工作，并自行发现错误；当你要求 Claude 先写测试再写实现代码时，效果尤其显著。
- **培养任务分类直觉**：学会区分适合异步执行的任务（外围功能、原型开发）与需要同步监督的任务（核心业务逻辑、关键修复）。产品边缘的抽象任务可以用“自动接受模式”（auto-accept mode）来处理，而核心功能则需要更紧密的监督。
- **编写清晰、详细的提示**：当组件名称或功能相似时，请求必须极其具体。你的提示越完善、越详细，就越能放心让 Claude 独立工作，而不会意外改动代码库中错误的部分。

# 安全工程中的 Claude Code

（原文页码：7）

安全工程团队专注于保障软件开发生命周期安全、供应链安全与开发环境安全。他们大量使用 Claude Code 来编写和调试代码。

## Claude Code 主要用例

- **复杂基础设施调试**：处理线上事件时，他们把堆栈跟踪（stack trace）和文档交给 Claude Code，让它沿代码库追踪控制流。这显著缩短了生产问题从发现到解决的时间——过去需要 10–15 分钟人工扫读代码才能理解的问题，现在约 5 分钟即可厘清。
- **Terraform 代码评审与分析**：对于需要安全审批的基础设施变更，他们把 Terraform 计划（plan）粘贴进 Claude Code，问“这会带来什么影响？我会不会后悔？”。这形成了更紧密的反馈闭环，让安全团队能更快评审并批准基础设施变更，减少开发流程中的瓶颈。
- **文档综合与运行手册**：他们让 Claude Code 摄取多个文档来源，生成 Markdown 运行手册（runbook）、故障排查指南和概览。他们把这些浓缩后的文档作为调试真实问题的上下文，形成比在完整知识库中检索更高效的工作流。
- **测试驱动开发工作流**：他们告别了过去“设计文档 → 东拼西凑的代码 → 重构 → 放弃测试”的模式，现在改为向 Claude Code 索取伪代码，引导它进行测试驱动开发（TDD），并在它卡住时定期介入引导，从而得到更可靠、更可测试的代码。
- **上下文切换与项目上手**：在为既有项目（如 “dependant”——一个用于安全审批工作流的 Web 应用）做贡献时，他们使用 Claude Code 编写、评审并执行以 Markdown 撰写、存放在代码库中的规格说明（specification），从而在几天而非几周内做出有意义的贡献。

# 推理（Inference）团队中的 Claude Code

（原文页码：9）

推理团队负责管理记忆系统——即在 Claude 读取你的提示并生成回复的过程中用于存储信息的系统。团队成员（尤其是机器学习新手）可以大量使用 Claude Code 来弥合知识差距、加速工作。

## Claude Code 主要用例

- **代码库理解与上手**：该团队高度依赖 Claude Code，在加入复杂代码库时快速理解其架构。他们不再手动检索 GitHub 仓库，而是让 Claude 找出哪些文件调用了特定功能，几秒钟就能得到结果，无需询问同事或手动检索。
- **覆盖边界情况的单元测试生成**：写完核心功能后，他们让 Claude 编写全面的单元测试。Claude 会自动补上被遗漏的边界情况，把原本需要耗费大量脑力的工作压缩到几分钟内完成，就像一个可供评审的编程助手。
- **机器学习概念解释**：没有机器学习背景的团队成员依赖 Claude 解释特定于模型的函数与设置。原本需要一小时 Google 检索和阅读文档的事，现在 10–20 分钟即可完成，研究时间减少 80%。
- **跨语言代码翻译**：在不同编程语言中测试功能时，他们说明想测试什么，Claude 就用所需的语言（如 Rust）写出逻辑，免去了仅为测试而学习新语言的需要。
- **命令回忆与 Kubernetes 管理**：他们不再死记复杂的 Kubernetes 命令，而是直接问 Claude 正确的语法，例如“如何查看所有 pod 或 deployment 状态”，从而获得基础设施工作所需的准确命令。

# Claude Code 用于数据科学与可视化

（原文页码：11）

数据科学与机器学习工程团队需要精良的可视化工具来理解模型表现，但构建这些工具往往需要精通并不熟悉的语言与框架。Claude Code 让这些团队无需成为全栈开发者，就能构建生产级（production-quality）分析仪表盘。

## Claude Code 主要用例

- **构建 JavaScript/TypeScript 仪表盘应用**：尽管团队“对 JavaScript 和 TypeScript 几乎一无所知”，他们仍然用 Claude Code 构建完整的 React 应用，用于可视化强化学习（RL）模型的表现与训练数据。他们放手让 Claude 从零编写完整应用——比如一个 5000 行的 TypeScript 应用——自己完全不需要读懂这些代码。这一点至关重要，因为可视化应用上下文相对较少，也不需要理解整个单体仓库，从而能快速做出工具原型，以便在训练与评估期间理解模型表现。
- **处理重复性重构任务**：面对合并冲突，或复杂度超出编辑器宏、又够不上正式开发工作量的半复杂文件重构时，他们把 Claude Code 当作“老虎机”来用——先提交当前状态，让 Claude 自主工作 30 分钟，然后要么接受它的方案，要么推倒重来。
- **创建持久化分析工具，而非一次性笔记本**：团队不再构建用完即弃的一次性 Jupyter notebook，而是让 Claude 构建可复用的永久性 React 仪表盘，供未来的模型评估反复使用。这一点很重要，因为理解 Claude 的表现“是团队最重要的事情之一”——他们需要理解模型在训练与评估期间的表现，而这“实际上并不简单，光靠看单个数字上下波动，简单工具根本提取不出多少信号”。
- **零依赖任务委派**：对于完全不熟悉的代码库或语言中的任务，他们把整个实现都委派给 Claude Code，借助它从单体仓库中收集上下文并执行任务的能力，自己完全不参与实际编码过程。这让他们能涉足专业领域之外的工作并保持产出，而不必花时间去学新技术。

# Claude Code 用于 API

（原文页码：13）

API 知识团队负责 PDF 支持、引文、网页搜索等功能，这些功能把额外的知识带入 Claude 的上下文窗口。在庞大而复杂的代码库中工作时，他们不断遇到陌生的代码段，需要花大量时间弄清楚某个任务该看哪些文件，并在动手改动前先建立上下文。Claude Code 改善了这种体验：它像一位向导，帮助他们理解系统架构、定位相关文件、解释复杂的交互关系。

## Claude Code 主要用例
