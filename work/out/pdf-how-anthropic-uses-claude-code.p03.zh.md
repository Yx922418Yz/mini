# 产品开发中的 Claude Code

（原文页码：6）

## 团队成效

- **功能实现更快**：成功实现 Vim 模式等复杂功能，其中 70% 的代码由 Claude 自主编写。
- **开发速度提升**：可以快速原型化功能、迭代想法，而不会陷入实现细节之中。
- **借助自动化测试提升代码质量**：Claude 生成全面的测试并处理常规缺陷修复，在减少人工投入的同时维持高标准。
- **更好的代码库探索**：团队成员无需等待同事回复，即可快速理解单体仓库（monorepo）中不熟悉的部分。

## Claude Code 团队的核心提示

- **构建自给自足的闭环**：让 Claude 通过自动运行构建、测试与 lint 来验证自己的产出。这使 Claude 能够更长时间地自主工作，并自行发现错误；当你要求 Claude 先写测试再写实现代码时，效果尤其显著。
- **培养任务分类直觉**：学会区分适合异步执行的任务（外围功能、原型开发）与需要同步监督的任务（核心业务逻辑、关键修复）。产品边缘的抽象任务可以用“自动接受模式”（auto-accept mode）来处理，而核心功能则需要更紧密的监督。
- **编写清晰、详细的提示**：当组件名称或功能相似时，请求必须极其具体。你的提示越完善、越详细，就越能放心让 Claude 独立工作，而不会意外改动代码库中错误的部分。

# 安全工程中的 Claude Code

（原文页码：7）

安全工程团队专注于保障软件开发生命周期安全、供应链安全与开发环境安全。他们大量使用 Claude Code 来编写和调试代码。

## Claude Code 主要用例

- **复杂基础设施调试**：处理线上事件时，他们把堆栈跟踪（stack trace）和文档交给 Claude Code，让它沿代码库追踪控制流。这显著缩短了生产问题从发现到解决的时间——过去需要 10–15 分钟人工扫读代码才能理解的问题，现在约 5 分钟即可厘清。
- **Terraform 代码评审与分析**：对于需要安全审批的基础设施变更，他们把 Terraform 计划（plan）粘贴进 Claude Code，问“这会带来什么影响？我会不会后悔？”。这形成了更紧密的反馈闭环，让安全团队能更快评审并批准基础设施变更，减少开发流程中的瓶颈。
- **文档综合与运行手册**：他们让 Claude Code 摄取多个文档来源，生成 Markdown 运行手册（runbook）、故障排查指南和概览。他们把这些浓缩后的文档作为调试真实问题的上下文，形成比在完整知识库中检索更高效的工作流。
- **测试驱动开发工作流**：他们告别了过去“设计文档 → 东拼西凑的代码 → 重构 → 放弃测试”的模式，现在改为向 Claude Code 索取伪代码，引导它进行测试驱动开发（TDD），并在它卡住时定期介入引导，从而得到更可靠、更可测试的代码。
- **上下文切换与项目上手**：在为既有项目（如 “dependant”——一个用于安全审批工作流的 Web 应用）做贡献时，他们使用 Claude Code 编写、评审并执行以 Markdown 撰写、存放在代码库中的规格说明（specification），从而在几天而非几周内做出有意义的贡献。
