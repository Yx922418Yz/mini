# Claude Code 用于产品设计（续）

（原文页码：18）

## 团队成效

- **核心工作流被重塑**：Claude Code 成为主力设计工具，Figma 和 Claude Code 有 80% 的时间都是打开着的。
- **执行速度提升 2–3 倍**：以往需要与工程师反复沟通的视觉与状态管理改动，如今可直接实现。
- **交付周期从数周缩短到数小时**：像 GA 发布文案这类本需一周协调的复杂项目，现在两次 30 分钟的通话就能完成。
- **两种截然不同的用户体验**：开发者获得的是“增强型工作流”（执行更快），而非技术用户获得的是“天哪，我居然成了开发者”的工作流（过去根本不可能的全新能力）。
- **设计与工程的协作更顺畅**：由于设计师提前理解了系统约束与可能性，沟通更好、问题解决更快。

## 产品设计团队的核心提示

- **请工程师提供正确的初始配置帮助**：让工程同事帮忙完成仓库初始化与权限设置——对非开发者来说技术上手颇具挑战，但一旦配置好，日常工作效率会发生蜕变。
- **用自定义记忆文件来引导 Claude 的行为**：写下明确的指令，告诉 Claude 你是一位几乎没有编程经验的设计师，需要详细解释和更小步、增量的改动，这会显著提升 Claude 回复的质量，也让它不那么令人望而生畏。
- **利用图片粘贴来做原型**：用 Command+V 把截图直接粘贴进 Claude Code——它非常擅长读懂设计并生成可运行代码，对把静态设计稿变成工程师能立即理解并继续开发的交互式原型，价值无可估量。

# Claude Code 用于强化学习工程

（原文页码：19）

强化学习（RL）工程团队专注于 RL 中的高效采样以及集群间的权重传输。他们把 Claude Code 主要用于编写中小型功能、调试以及理解复杂代码库，并采用包含频繁打检查点（checkpoint）与回滚的迭代式方法。

## Claude Code 主要用例

- **监督式自主的功能开发**：团队让 Claude Code 编写中小型功能的大部分代码，同时提供监督，例如为权重传输组件实现身份验证机制。他们以交互方式推进，让 Claude 主导，但在它偏离方向时加以引导。
- **测试生成与代码审查**：在自己实现改动后，他们让 Claude Code 补充测试或审查代码。这种自动化测试工作流在常规但重要的质量保障任务上节省了大量时间。
- **调试与错误排查**：他们用 Claude Code 调试错误，效果参差不齐——有时它能立刻定位问题并补上相关测试，有时则难以理解问题所在；但总体而言，在奏效时确实有价值。
- **代码库理解与调用栈分析**：他们工作流中最大的变化之一，是用 Claude Code 快速获取相关组件和调用栈的摘要，取代了手动读代码或生成大量调试输出的做法。
- **Kubernetes 操作指导**：他们经常就本需大量 Google 检索的 Kubernetes 操作询问 Claude Code，在配置和部署问题上即时得到答案。
