## Claude Code 用于数据基础设施

### 团队成效

**无需专业知识即可解决基础设施问题**

借助 Claude Code 诊断问题并给出确切的修复方案，解决了通常需要引入系统或网络团队同事才能处理的 Kubernetes 集群问题。

**加速上手（onboarding）**

新的数据分析师与团队成员能够快速理解复杂系统，无需大量指导即可做出有实质意义的贡献。

**增强支持工作流**

能够处理大得多的数据量并识别异常（例如同时监控 200 个仪表盘），这是人工审查不可能完成的。

**实现跨团队自助服务**

没有编程经验的财务团队现在可以独立执行复杂的数据工作流。

### 数据基础设施团队的实用建议

**编写详尽的 Claude.md 文件**

你在 Claude.md 文件中把工作流、工具和期望记录得越好，Claude Code 的表现就越好。这让 Claude Code 在已有既定模式的例行任务（例如搭建新的数据管道）上表现出色。

**处理敏感数据时用 MCP 服务器而非 CLI**

他们建议使用 MCP 服务器（MCP Server）而不是 BigQuery CLI，以便对 Claude Code 能访问的内容保持更好的安全控制——尤其是在处理需要留痕或存在潜在隐私顾虑的敏感数据时。

**分享团队使用会话**

团队组织了分享会，让成员相互演示各自的 Claude Code 工作流。这有助于传播最佳实践，并展示他们自己未必能发现的不同用法。

## Claude Code 用于产品开发

Claude Code 团队用自家的产品来构建 Claude Code 的更新，扩展该产品的企业级能力与智能体循环（agentic loop）功能。

### Claude Code 主要使用场景

**用自动接受模式快速做原型**

工程师通过启用「自动接受模式」（auto-accept mode，快捷键 shift+tab）并搭建自主循环（Claude 写代码、运行测试、持续迭代）来实现快速原型开发。他们会把不熟悉的抽象问题交给 Claude，让它自主工作，然后审阅完成度约 80% 的方案，再接手做最终打磨。团队强调要从干净的 git 状态开始，并定期提交检查点（commit checkpoint），这样一旦 Claude 跑偏，就能轻松回退错误的改动。

**核心功能的同步编码**

对于涉及应用业务逻辑的更关键功能，团队与 Claude Code 同步协作，给出带有具体实现指令的详细提示词（Prompt），并实时监控过程，以确保代码质量、符合风格指南（style guide）和架构合理，同时让 Claude 处理重复性的编码工作。

**构建 Vim 模式**

他们最成功的异步项目之一，是为 Claude Code 实现 Vim 键位绑定。他们让 Claude 构建整个功能（尽管它并非优先事项），最终实现中约 70% 来自 Claude 的自主工作，只需少数几次迭代即告完成。

**测试生成与缺陷修复**

他们在实现功能之后用 Claude Code 编写全面的测试，并处理拉取请求（Pull Request）评审中发现的简单缺陷修复。他们还利用 GitHub Actions 集成，让 Claude 自动处理拉取请求上的评论，例如格式问题或函数重命名。

**代码库探索**

在处理不熟悉的代码库（例如单体仓库（Monorepo）或 API 一侧）时，团队用 Claude Code 快速理解系统的运作方式。与其等待 Slack 回复，他们直接向 Claude 询要解释和代码引用，从而在上下文切换（context switching）上节省大量时间。
