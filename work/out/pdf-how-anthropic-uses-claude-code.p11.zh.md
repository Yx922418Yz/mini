# Claude Code 用于法务（续）

（原文页码：22）

## 工作方式与影响

- **在 Claude.ai 中规划，在 Claude Code 中构建**：他们采用两步流程——先用 Claude.ai 做头脑风暴与规划，再转到 Claude Code 实现，并要求它放慢速度、一步步来，而不是一次性输出全部内容。
- **视觉优先的方法**：他们经常用截图向 Claude Code 展示希望界面长什么样，然后基于视觉反馈进行迭代，而不是用文字去描述功能。
- **原型驱动的创新**：他们强调要克服分享“傻乎乎”或“玩具”级原型的恐惧，因为这类演示能启发他人看到自己原本想不到的可能性。

## 安全与合规意识

- **MCP 集成顾虑**：作为产品律师，他们会立即识别深度 MCP 集成带来的安全影响，并指出随着 AI 工具接入更多敏感系统，保守的安全姿态将会形成障碍。
- **合规工具的优先级**：随着 AI 能力不断扩张，他们主张尽快构建合规工具，同时也意识到创新与风险管理之间的平衡。

## 法务部门的核心提示

- **先在 Claude.ai 中充分规划**：在转到 Claude Code 之前，先用 Claude 的对话界面把整个想法梳理清楚；然后请 Claude 把所有内容总结成一份分步实现的提示。
- **增量式、可视化地推进**：请 Claude Code 放慢速度，一次只实现一步，这样你复制粘贴时就不会不知所措。大量使用截图来展示你希望界面呈现的样子。
- **不完美也要分享原型**：克服把“玩具”项目或未完成工作藏起来的冲动——分享原型能帮助他人看到可能性，并激发通常互不接触的部门之间的创新。
