# Claude Code 用于数据科学与可视化（续）

（原文页码：12）

## 团队成效

- **实现 2–4 倍的时间节省**：那些虽然繁琐但仍可手动应付的日常重构任务，如今完成得快得多。
- **用不熟悉的语言构建复杂应用**：尽管几乎没有 JavaScript/TypeScript 经验，仍构建出 5000 行的 TypeScript 应用。
- **从一次性工具转向持久化工具**：不再使用用完即弃的 Jupyter notebook，转而构建可复用的 React 仪表盘来做模型分析。
- **直接的模型改进洞见**：亲身使用 Claude Code 的经验，为后续模型迭代中更好的记忆系统与 UX 改进提供了依据。
- **实现可视化驱动的决策**：借助高级数据可视化工具，更好地理解 Claude 在训练与评估期间的表现。

## 数据科学与机器学习工程团队的核心提示

- **把它当作老虎机**：让 Claude 开始工作前先保存当前状态，让它跑 30 分钟，然后要么接受结果，要么推倒重来，而不是硬着头皮去纠正它。重新开始的成功率往往高于试图修补 Claude 的错误。
- **必要时打断以求简化**：在监督过程中，不要犹豫，直接叫停 Claude 并问它“你为什么要这样做？试试更简单的办法”。模型默认倾向于给出更复杂的方案，但对“用更简单办法”的要求响应良好。

# Claude Code 用于 API

（原文页码：13）

API 知识团队负责 PDF 支持、引文、网页搜索等功能，这些功能把额外的知识带入 Claude 的上下文窗口。在庞大而复杂的代码库中工作时，他们不断遇到陌生的代码段，需要花大量时间弄清楚某个任务该看哪些文件，并在动手改动前先建立上下文。Claude Code 改善了这种体验：它像一位向导，帮助他们理解系统架构、定位相关文件、解释复杂的交互关系。

## Claude Code 主要用例

- **第一步工作流规划**：团队把 Claude Code 当作任何任务的“第一站”，让它指出修复缺陷、开发功能或做分析时该看哪些文件。这取代了以往那种先手动翻找代码库、收集上下文才能开工的耗时流程。
- **跨代码库的独立调试**：团队现在有信心去处理代码库中不熟悉部分的缺陷，而不必向他人求助。他们可以问 Claude“你觉得能修好这个缺陷吗？我看到的行为是这样的”，往往立刻就有进展——这在以前，考虑到所需的时间投入，是做不到的。
- **通过“自用测试”进行模型迭代验证**：Claude Code 会自动使用最新的研究模型快照，这使它成为团队体验模型变化的主要方式。这让他们在开发周期中直接获得关于模型行为变化的反馈，而这在此前的版本发布中从未体验过。
- **消除上下文切换开销**：他们不再需要复制代码片段、把文件拖进 Claude.ai 并大段解释问题，而是直接在 Claude Code 里提问，无需额外收集上下文，大幅降低了心智负担。
